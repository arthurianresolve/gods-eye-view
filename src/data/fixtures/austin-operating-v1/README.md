# Austin operating workload fixture

This directory backs the `austin-operating-v1` browser fixture. It composes the production adapters for CelesTrak TLE groups, Austin CCTV metadata, ALPR vector tiles, radio directory data, military-installation records, and GFS wind. The route and source responses are deterministic; the fixture is not a claim that these records describe the live Austin operating picture.

The fixed harness epoch is **2026-10-12 18:00 UTC**. TLE element epochs remain exactly as acquired and are newer or older by catalog entry; successful parsing and finite propagation do not establish current orbital accuracy. The wind grid retains its source valid time **2026-10-08 12:00 UTC**, so it is 4 days 6 hours old at the fixture epoch and ages with the simulated clock. Acquisition timestamps describe when bytes were fetched, not when their underlying observations occurred.

The 250 CCTV metadata rows come from the Austin Open Data camera catalog. Only deterministic generated SVGs are served for image requests; they are prominently marked fixture-only and are not captured camera feeds. Radio (750 entries) and military-installation (699 entries) payloads are deterministic synthetic data in the native endpoint schemas. Their counts exercise the declared application caps; they are not verified provider population counts or geographic coverage. The route uses the application’s native camera, ALPR viewport, and installation viewport logic. Startup and each sample report the actual observed viewport subsets separately from source/catalog counts.

The ALPR TileJSON and twelve required z10 tiles are bounded public snapshots from [deflock-data](https://github.com/flockhopper3/deflock-data), whose repository documents the hourly tile endpoint. The earlier z11 files retained in `alpr/` are historical acquisition records and are not used for the current route coverage gate. The tile data is derived from OpenStreetMap. `acquisition.json` files preserve URLs, response metadata, fetch timestamps, and hashes. Do not rewrite source observation times to the harness clock. Changes to these bytes, route tiles, fixture construction, or source adapters require updating the manifest and their contract tests. A short smoke capture only checks wiring. Performance acceptance requires the full matched workload and its independent readiness, cleanup, build, foreground, and hardware gates.
