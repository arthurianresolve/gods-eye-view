# Datacenter collection candidate

This isolated current-dev candidate enables owned point/stem collections only for `local-datacenters` through `datacenterSurfaceRenderer`. The default remains Entity rendering, and the dams and submarine-cable layers remain on their existing renderers. The datacenter fixture binds the full bundled source inventory, source identities, native point/stem owners and picks, exact pixels, camera/LOD state, and teardown ownership.

The five-pair fresh-viewer benefit harness keeps latency and forced-GC heap runs separate. It records source-ready and first usable frame timing separately from capture/readback, and reports JavaScript heap only; it does not estimate native or GPU memory. Workflow choices are `infrastructure-datacenters` for the correctness/lifecycle comparison and `datacenter-benefit` for the alternating benefit harness. Both paths explicitly select `local-datacenters`.

The earlier hosted datacenter comparison on the predecessor candidate reported median source-ready at -10.85%, first usable frame at -28.63%, and post-GC enabled JavaScript heap at -16.06% versus Entities, with 20 exact image pairs. Those measurements remain historical and do not validate this current-dev integration. This branch still needs its own rendered/benefit checks, physical Windows coverage, and mixed-layer acceptance before any rollout decision. No default renderer change is made here.

Independent review of the isolated integration passes 92 focused tests covering the factory boundary, layer lifecycle, native picking, fixture camera, and runtime/benefit report validation. Datacenter evidence requirements include complete source hashes, identity, Graphics ownership and native pick provenance. Missing fields remain failures. The existing `--infrastructure` fixture route and historical dam report validation retain their original meaning; the new executable route explicitly selects datacenters.
