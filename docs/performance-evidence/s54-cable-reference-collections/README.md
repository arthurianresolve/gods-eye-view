# Cable reference collection experiment

This isolated S54 prototype moves only the 2,629 reference point/stem pairs into owned Cesium collections when the caller explicitly selects `referenceRenderer: collections`. The production default remains Entity rendering. All 1,913 clamped ground cable segments and 1,917 landing pin billboards retain their existing GeoJSON renderers and source picking. Metadata Entities, labels, source IDs and per-kind appearance remain.

[Focused test evidence](review.json) includes complete bundled-source ingestion, native pick mappings, camera sweeps, teardown/re-enable and partial-attachment failures. Collections are explicitly destroyed when removal does not destroy them. These are actual-Cesium Node checks, not rendered, GPU, or performance evidence. Visual equivalence, map-stack/terrain checks and matched activation/retained-memory comparisons are still required before accepting this optimization.

The first full-source hosted fixture at `e88a1a7` failed in the baseline Entity camera-change phase before the candidate ran. [Failure evidence](failed-38132781148/review.json) is preserved. Code review identified a readiness race: stable frames can precede the camera moveEnd event consumed by the cable layer. The fixture now requires a moveEnd at the completed-flight pose and a subsequent completed frame, followed by stability, under one existing twelve-second deadline. Intermediate-pose events are rejected; timeout cancels the flight and all listeners/timers are released. Native-pick failures preserve bounded partial-pick and best-effort image diagnostics without masking the original error. Eleven focused gate/validator tests, syntax and formatting pass; whether this explains the hosted failure awaits the new rendered run. Production runtime is unchanged.

The next hosted run at `58f3b5d` still entered the camera-change pick failure path, where an unsupported cable-layer diagnostic method masked the original evidence. [Preserved report](failed-38134300530/review.json). The failure builder now records the original reason and partial picks before independently guarded optional diagnostics. Thirteen focused tests cover the real public cable layer API, throwing accessors, final camera pose and validation contracts. The camera-change pick cause remains unresolved until a rendered report supplies the missing observations.

## Camera-change readiness investigation

[Run 38134780602](https://github.com/arthurianresolve/gods-eye-view/actions/runs/38134780602) at `ff84ea0` preserves five baseline samples and the actual failure: the final camera sweep completed and point picking worked, but all 165 stem pick probes missed. The copied frame contains points without their stems. [Failure review](failed-38134780602/review.json) retains the original report; the candidate never ran. DataSourceDisplay readiness alone does not prove that replacement primitive owners have finished. The next fixture revision observes those public owners, including hidden replacements, before accepting stable frames, retains bounded per-case observations, and keeps the same twelve-second settle deadline. This is a fixture gate and diagnostic change, not an established engine root-cause fix or a production renderer change. The current report contract rejects unready, truncated or absent primitive observations. Eighteen focused camera/diagnostic/observer/report tests pass; new rendered evidence is pending.

Review also found that the report validator rejected a real static Entity stem represented by `Primitive` with `PolylineColorAppearance`. The corrected type check matches the native picking path, still requires the exact Entity owner, and rejects unrelated appearances. Default camera-sweep metadata now explicitly records its non-applicable fields as null, matching the existing contract. Neither reporting correction explains the observed null native picks.
