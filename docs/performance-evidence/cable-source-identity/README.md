# Cable source mapping correction

Status: implemented with 39 focused checks passing; whole integration and rendered validation pending.

The old ingestion paired expanded Cesium Entities with source features by array index. A multipart source shifts every following association; the bundled 712 cable features expand to 1,913 Entities. The old path therefore styled/picked wrong sources and omitted 1,201 segment records. The [negative control](negative-control.json) runs baseline ingestion from e503504 and the corrected ingestion over the same three-segment fixture: baseline assigns North's second segment to South and omits South's segment; candidate assigns all three correctly with exactly the same native Entity IDs.

Each load now chooses a temporary property name absent from all provider properties, copies source ordinals into the GeoJSON passed to Cesium, groups expanded Entities by their true parent, and removes the temporary field from copied features and Entity PropertyBags before publication. Original metadata and Cesium ID suffixes remain intact. Each source still gets one feature record and reference stem, while every segment receives that source's style, visibility record and pick mapping. Correcting previously incorrect source colors and picks is intentional bug-fix behavior, not a claim of pixel equivalence to the broken baseline.

[Focused evidence](review.json) binds source/test hashes and the [raw log](focused.log). Tests load all 712 bundled sources with actual Cesium, verify 1,913 correctly styled/pickable segments and 712 reference stems, cover duplicate IDs and enumeration order, metadata-name collisions, cancellation at both GeoJSON boundaries, malformed binding, failed load and retry, deferred additions, teardown and current source ownership. Adopted formatting and package boundaries pass. No dependency, primitive representation, landing marker appearance or drawing settings change is included. This correction does not complete S54 or S60.
