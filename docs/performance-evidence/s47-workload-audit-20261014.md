Common controls are substantially present. `buildProvenance.mjs` and its tests reject wrong source/recipe identities, dirty checkout, failed or changed builds, and served bytes that differ from the local receipt. Workload contracts pin their own fixed clocks, routes, fixtures and populations; `pairedReport.mjs` requires baseline/candidate equality and rejects nonzero injected delay. The synthetic delay frame-budget test exercises a deliberately slow sample. Missing coverage is specifically an actual CLI `--inject-delay-ms` negative run and the family identity/export cases above; the acceptance check asks for the negative control to fail, so report-level mutation alone should not be mistaken for an executed injected-delay control.

The acceptance distinction remains: producer/validator fixes are code work; the five matched baseline/candidate 30-second-warmup/60-second trials for timed families, complete identity/visual conditions, and primary physical Windows renderer are qualification work. This audit does not mark either category complete. In particular, the preserved smoke reports and native map/weather controls are integration evidence only. The weather sidecar replay after `1a03bc59` establishes that the corrected validator accepts that actual completed producer report, while its original hosted wrapper outcome stays failed until a new hosted run validates the revised code.
